# Threat memory and Mass representation engineering

Engineering review: 5 September 2026. Authority: TDD v2 §§8.3–8.6, preserving the approved Narrative activity/controller/GAS architecture. This closes source-level perception gaps, not the full R4 battlefield scale acceptance gate.

## What existed and what changed

| Gap | Existing implementation | Native change and disposition | Dependencies, risk and validation |
|---|---|---|---|
| Finite threat information | `ANarrativeNPCController` owns activities, focus and attack tokens. AI Perception and target-generating activities are configured in Blueprint assets, which are unavailable in this workspace. There was no native per-source confidence/expiry contract. | **Extend** this controller, not a parallel threat component. At most 128 observations record weak target identity, source, strength, confidence, last-known position, absolute observation/expiry times and faction-sharing provenance. Numeric inputs are validated; confidence decays to zero at an exclusive expiry boundary. | No new module or sensor component. Moderate combat-behavior risk. Portable production policy tests cover 36,660 decay/sharing boundaries. Native automation must pass with the actual Blueprint generators. |
| Acquisition and forgetting | Native bot repertoire selection validated hostility, health, ranges, LOS and attack slots, but a live actor pointer could remain a targeting authority indefinitely. | **Extend** the existing bot context gate with `CanDirectlyTargetThreat`, covering selection, post-token recheck and owned execution validation. Direct confidence must reach 0.65. Lost sight and cloak revoke direct tracking. Stale attack blackboard/focus state becomes a finite recorded investigation location; expiry clears owned investigation state and calls actual Perception forgetting. | Authored activities still own goal creation and movement decisions. No automatic alternate combat behavior graph is installed. An activity must use the finite location for investigation and must not restore live actor pursuit from a stale goal. Native attack acquisition/steering callers use the same controller predicate; area damage retains its ordinary hostile-collateral rules. |
| Real sources and source debug | Native Perception exists, but no source/provenance view could prove the broader TDD contract. | **Preserve and bind** the existing Perception component. Sight, hearing and damage events update memory. Current sight alone may sample a target's new location. Hearing, commands, spoof reports and ally alerts remain indirect. Network and Echo/corruption reports require selected-archetype opt-in. `GetThreatDebugSnapshot` and the controller `DisplayDebug` Threat flag show source, strength, current confidence, position, sharer, shared factions and expiry. | Selected units and authored weapon/alarm/Echo/Viewmaker producers call `ReportThreatObservation`; this does not claim those missing assets automatically emit every TDD stimulus. No lighting or stance modifier is invented. Registered but deactivated sensing cannot renew stale sight. |
| Faction sharing | Narrative faction attitudes existed; indiscriminate information transfer had no native lifetime/provenance contract. | **Extend** using mutual friendly attitude, exact shared faction membership and a finite radius. Alerts retain the sender's position, never exceed originating expiry, carry sender/faction provenance and cannot be relayed or laundered from spoof reports. Automatic sharing is throttled and bounded to 16 successful deliveries and 256 inspected controllers per update. | Recipients must already participate through Perception, explicit reports or `bRequireThreatMemoryForTargeting`. Legacy controllers without Perception refuse alerts and retain their existing targeting behavior. Crowded scenes can omit recipients once the budget is exhausted; encounter measurements are still required. |
| Staging, restore and callbacks | The director and wave coordinator pause existing AI and own Busy/invulnerability contributions. Controller polling could otherwise continue while those systems are paused. Blackboard and path callbacks can synchronously change possession. | **Extend** with independent weak-owner `SetThreatMemorySuspended` contributions. Hidden observers/targets, uninitialized ASC avatar bindings and suspended controllers cannot acquire/share/target. Suspension clears transient sensor memory and requires fresh information after release. Cleanup rechecks controller, pawn, blackboard and mutation generation after callback boundaries; unrelated valid focus and dialogue/cinematic focus retain their owners. | The existing director and coordinator acquire/release the controller API using their own identities. This is transient state, not a second checkpoint record. Runtime tests exercise multiple owners, a staged encounter and possession replacement. |
| Deferred Mass representation lifetime/order | `UMassNarrativePedRepresentationActorManagement::SetActorEnabled` captured an actor reference in deferred work and skipped requests based on the actor's pre-flush collision flag. Disable then enable before a flush could finish disabled; matching collision could leave visibility/tick wrong. | **Refactor** the existing deferred command. Every request is queued, so ordering is retained. Execution checks weak actor lifetime, the existing MassAgent component and entity handle when present, and updates collision, visibility and tick independently. | Moderate streaming/pooling risk. Engine automation uses the real Mass command buffer for same-buffer disable/enable, visibility mismatch, changed component association and destruction. Actual pooled/LOD content still needs an engine soak. |

Observations are server-local and deliberately neither saved nor replicated. Pawn changes and death clear them; outgoing death bindings and ASC ownership are removed before reassignment. A dedicated assignment generation prevents callback reentry from installing an older pawn. Callback-emitting cleanup runs after the new pawn and Narrative identity agree, and unpossess exposes no outgoing ASC. On resume or retry the sensor must reacquire the target. Activation/deactivation callbacks and observed sight-readiness loss discard cached engine stimuli while retaining finite investigation records; activation alone cannot reinterpret an old successful stimulus as fresh sight. AI Perception is normally event-driven, so merely changing a component's tick interval is not proof of reduced sensing cost.

## Remaining native engineering, not editor-only work

**The native campaign C/D bridge is now implemented for explicitly eligible participants; engine acceptance remains open.** [CampaignMassEngineering.md](CampaignMassEngineering.md) documents the actual director-owned snapshot-to-entity-to-fresh-actor path, native campaign visualization trait, noncombat proxy, finite-route processor, and existing Narrative representation-manager/spawner integration. Campaign entities never acquire the randomized pedestrian fragment. Unsupported combatants stay actors and receive an explicit refusal reason; no claim is made that every campaign actor can migrate.

The owner receipt now identifies the exact entity, participant GUID, encounter, director, entity generation and local binding epoch even on a plain proxy without a MassAgent component. Current C/D records live on the existing encounter director beside its existing NPC checkpoint records; proxies are neither savable nor GAS avatars. Promotion restores and verifies state before releasing only the new actor's director suspension, rebinds the existing encounter coordinator, and retains required mission/wave ownership while demoted. The existing Narrative snapshot animation blend contract is reused, with skeleton compatibility validation; authored ABP consumption still requires UE execution.

The TDD's platform frame/memory budgets, StateTree/activity content acceptance, all authored sensor producers and 40–100 visible Tier C agents are unmeasured. The native automatic sharing scan is bounded, but large populations need profiling and potentially routing through the existing encounter/faction membership lists. Source confidence defaults are starting tuning values, not validated stealth feel. These remain explicit engineering/content/runtime gates.

## Validation and definition of done

Executed: `Tests/Portable/NarrativeThreatPolicyTests.cpp`, compiled as C++17 with `-Wall -Wextra -Werror -pedantic`, UBSan and no sanitizer recovery. It passed 36,660 monotonic decay, exact expiry, cloak, indirect-confidence and sharing-lifetime boundary checks plus malformed numeric checks.

Authored UE automation, **not executed**:

1. `ProjectVelkorran.Campaign.Threat.SelectionCloakAndExpiry`: actual native GAS activation, active payload invalidation, recorded location instead of hidden actor position, and expiry cleanup.
2. `ProjectVelkorran.Campaign.Threat.PerceptionLossAndForgetting`: actual Perception stimulus registration/processing, authored strength retention, deactivated sensor behavior, activation without a new stimulus, fresh reacquisition, sight-enabled transitions, lost-sight callback and engine forgetting.
3. `ProjectVelkorran.Campaign.Threat.FactionSharingAndLifecycle`: legacy recipient compatibility, faction/attitude/radius restrictions, finite source provenance, relay rejection, death and pawn changes.
4. `ProjectVelkorran.Campaign.Threat.SuspensionAndCallbackOwnership`: multiple suspension owners, hidden actors, valid independent focus and possession changed synchronously by a blackboard observer.
5. `ProjectVelkorran.Campaign.Threat.PawnAssignmentReentryAndOutgoingASC`: direct `SetPawn` callback reentry preserves the newest pawn, ASC, focus and blackboard location; superseded death notifications cannot erase current memory; unpossess clears ASC ownership.
6. `ProjectVelkorran.Campaign.Mass.DeferredRepresentationOrderingAndLifetime`: real Mass command buffer ordering, independent state reconciliation, association changes and destruction.

The companion encounter integration test in `SovCoordinationRuntimeTests.cpp` exercises director/wave suspension ownership against the actual controller. [NativeThreatAttackIntegration.md](NativeThreatAttackIntegration.md) records native Hound, Drone, Handler and released-rocket acquisition/steering call sites and their three additional runtime suites.

Done for this source slice requires UHT/UBT and these runtime tests to pass, then Level 1/2 encounters must verify: occlusion and cloak produce last-known investigation without actor pursuit; hearing and alerts cannot authorize precision fire; dead/staged/initializing participants cannot be acquired; retry restores independent suspension ownership; direct ability activation cannot bypass memory; and thrown/detonated collateral damage still works after a target cloaks. Full R4 completion additionally requires C/D engine acceptance and measured performance evidence. No UE installation or assets are available here, so neither runtime completion nor performance compliance is asserted.
