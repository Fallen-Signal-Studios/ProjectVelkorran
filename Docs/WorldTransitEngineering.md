# Native world transit and traversal

This source pass implements TDD v2 §§11.6–11.8 and the record-ordering part of §15.11 using Narrative's existing interaction and save owners. It does not introduce a second interaction, movement, inventory or world-state store.

## Entry and cancellation contract

Use the normal Narrative primary-focus/hold action. The native owners additionally validate actual authority, ready living pawn and current ASC avatar, entry volume, mission/beat/protagonist requirements and non-Busy state. Transit also checks line of sight and unique `TransitId`; traversal requires unique `TraversalId` and full capsule clearance. Neither accepts a caller-provided alignment-success boolean.

Traversal path points are capsule centers in anchor space, not feet positions. There must be 2–32 authored points. Each segment is at most 1,500 cm and total path length at most 5,000 cm. The adjustable duration is 0.1–30 seconds. The final point must satisfy the same safe-floor/capsule/recovery-exclusion contract as checkpoint recovery. Each direction uses its own authored entry anchor; this keeps per-direction capability and mission requirements explicit.

The moving transit box is the collision authority. Visual meshes have collision disabled. Doors expose passage links only when open; lifts expose boarding/exit links only at the currently occupied endpoint. Disabled links use the null nav area. The lift does not create a traversable link between floors while its platform is absent.

`OnTransitChanged` and `OnTraversalCompleted` are presentation notifications after native state resolution. They do not grant campaign facts. Mission state changes remain owned by the campaign's existing validated journal/beat API.

Carry targets use their existing Narrative actor record and component serializer. The component requires a movable, non-simulating upright capsule root; it refuses simulated child bodies as well. It does not create inventory entries, a second NPC Health model or a ragdoll simulation. `RequiredProtagonist` permits authored heavy-force capability restrictions. A negative local X carry offset supports an authored drag pose while the conservative upright collision body remains native.

Carry start and end are protected by a lease epoch. Actor, ASC/avatar and controller ownership are rechecked after external callbacks. Cleanup snapshots and retires handles before removing effects or resuming movement/activity, so callbacks cannot resurrect or recursively cancel a retired lease. Other Busy/movement locks and a reused AI controller are preserved. Saved target state is rejected while carrying, releasing or waiting for a safe placement. A successful rescue saves `bRescued` and the existing campaign beat; repeated delivery cannot award it again.

`RequestRelease` searches clear nearby floor positions and then the validated origin. If dynamic geometry blocks every release point during forced cancellation, player control is released, the target detaches without enabling collision inside geometry, and `OnRecoveryRequired` explicitly requests clearing the origin or loading the existing checkpoint. The component retries safe placement; unresolved placement cannot be saved as success. This failure is surfaced rather than teleporting a living actor into blocked geometry. The normal Narrative registry includes noncolliding bounds and ignores attached actors in LOS, so carried targets remain interactable; their lower prompt priority lets the rescue destination take precedence. Bind the existing set-down method to a contextual cancel action as an additional accessibility option.

## Validation

Executed: the production `SovWorldMotionPolicy` is compiled by the portable runner with warnings as errors and undefined-behavior sanitizer. Tests cover 100 starts at each of 30/60/120 Hz, duration overshoot and invalid delta handling, all endpoint-save/link-admission combinations, and timeout bounds. This is timing/state-policy validation, not a physics substitute.

Added Unreal automation, requiring execution in UE 5.7:

- `ProjectVelkorran.World.Traversal.RepeatedEntry30And60`: 100 native starts at each frame profile, endpoint arrival, no resource spending, tag and input cleanup.
- `ProjectVelkorran.World.Traversal.ObstructionAndSlowFrame`: complete-path preflight rejection, a blocker inserted after start, and a one-frame corner crossing that cannot take a blocked shortcut chord.
- `ProjectVelkorran.World.Transit.StableEndpointSave`: actual SaveGame archive acceptance/rejection for origin, unresolved streaming and broken midpoint.
- `ProjectVelkorran.Campaign.Save.ComponentOrderAndPreflight`: actual component restore order, duplicate record rejection before mutation and unknown-phase rejection.
- `ProjectVelkorran.World.Carry.OwnershipReleaseAndSave`: actual attachment, slow-walk state, stable-only serialization, preservation of another Busy owner and safe detachment on avatar loss.
- `ProjectVelkorran.World.Carry.RescueRequiresDestination`: no remote rescue completion, native spatial release, actual campaign journal commit and duplicate prevention.
- `ProjectVelkorran.World.Carry.ReentrantLeaseRetirement`: a synchronous GAS tag callback cancels during pickup; the late returned GE handle is removed and the target remains safe and serializable.

The executed carry policy suite covers all 32 rescue-admission combinations and 33,744 body-size combinations plus invalid values (33,778 checks). At the final local run, all 25 portable suites passed. These do not substitute for the authored Unreal automation above.

UE/UHT/UBT and map physics could not run in this environment. Required acceptance remains collision tests with every supported capsule, all lift riders, interrupted power, destruction, navmesh updates, source unload, streaming timeout and disk failure at both travel boundaries. No claim is made that an unauthored level is playable.

The implementation uses Epic's documented [smart-link API](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/NavigationSystem/UNavLinkCustomComponent) and explicitly sweeps the moving primitive because [component movement does not sweep arbitrary visual children](https://dev.epicgames.com/documentation/unreal-engine/BlueprintAPI/Transformation/SetRelativeLocation). Engine-version compilation remains a separate validation gate.
