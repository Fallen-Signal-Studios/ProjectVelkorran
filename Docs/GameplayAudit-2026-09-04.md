Evidence grades used below:

- **Implemented:** substantive source call chain exists. This does not certify its binary asset integration or runtime behavior.
- **Partial:** some gameplay contract exists but a required call, payload, consumer, or lifecycle is absent from tracked source.
- **Weak:** existing behavior has a specific consistency, recovery, or validation gap.
- **Unverified content:** the repository cannot establish whether local Blueprint/assets supply the missing piece. Do not call this missing from Matthew's local project.
- **Missing native:** no corresponding tracked project implementation was found; suitable Narrative primitives may still be reusable.

The exact snapshot contains 933 blobs. 927 text/source/configuration files were reproduced with matching Git blob hashes. Six PNG plugin/template resources could not be materialized; they are unrelated to gameplay inspection. No `.uasset`, `.umap`, World Partition External Actors, or local content configuration can be inspected. `Content/` is excluded. Thus a source audit can establish mechanisms and defects but cannot certify Level 1, Level 2, animation timing, HUD bindings, enemy composition, or asset grants.

Unreal Editor, UnrealBuildTool, the .NET runtime, and a configured remote Unreal runner are unavailable. There are no tracked CI workflows and no Actions runs at the audited commit. `.uproject` specifies 5.7 and enables ZenDyn, which is not tracked, plus MetaHuman dependencies. These are real compilation/content prerequisites, not evidence that the code fails to compile.

## Actual current state

This is a substantial combat framework with a partially assembled campaign, not a verified two-level playable build. The strongest systems are the unified Narrative GAS damage path; native protagonist component composition; guarded/deflected hit resolution; delayed Shield and approved Health recharge; Poise lifecycle; transient combat sustain; dismemberment presentation/state; and the new command-link/handler/hound transactions.

The weakest connection is from available mechanics to repeatable encounters and campaign recovery. Selene can earn Echo from implemented precision/deflection/link mechanisms, but all five revised spender classes at baseline still depend on unseen Blueprint payload work. Three of Tarrik's five revised spenders have native authoritative payloads. Campaign framework classes mostly establish ownership seams: they do not implement independent protagonist saves, mission progression, checkpoint encounter restoration, or M01-to-M02 handoff.

## Vertical-slice roadmap

Priority balances immediate playability, reuse, and dependency risk. S1 completes one missing player action with existing enemies. S2 makes those enemies use their authored kits. S3 makes a fight repeatable. S4 joins those proofs into the first two missions. Fix a reproducible build blocker before any slice when actual Unreal validation exposes one.

### S1 — Selene breaks a shielded command formation (selected)

**Playable result:** earn Echo through existing precision/deflection, charge Axiom, release a directed pulse, collapse hostile Shields without Health damage, pause recharge, interrupt eligible drones, sever an in-range visible command link, receive the existing one-time +12 Echo, exploit revealed weak points and the hound's lost coordinated charge.

**Files/classes:** extend `P/Public/Abilities/SovGameplayAbility_SeleneEcho.h` and its existing Axiom class; move native Axiom behavior into `P/Private/Abilities/SovGameplayAbility_SeleneAxiomNullPulse.cpp`; native effect shells in `P/{Public,Private}/Effects/SovGameplayEffect_AxiomNullPulse.*`; reuse `SovCommandLinkComponent`, `SovSeleneEchoGenerationComponent`, `SovShieldComponent`, `UNarrativeDamageExecCalc`, `UNarrativeAttributeSetBase`, and current NPC abilities. Add tests under `P/Private/Tests/` and validation script/docs.

**Work:** authoritative charge clock and input release/full-charge fallback; finite tuning validation; source weapon revalidation; range/cone/LOS target filtering and deduplication; typed result feedback; exact Shield-only damage through Narrative; bounded duration GEs; mechanical-target-only disable; interruption and timer cleanup; exactly-once release/Sever reward.

**Validation/tests:** 30 Echo becomes 12 after one fresh hostile link; 100 becomes 82; no repeated reward; zero/partial/full Shields retain Health; suppression expires; guard/deflection do not absorb EMP; friendly/dead/immune/outside-cone/occluded targets unchanged; Hound Bite/Pounce survive link sever; native drone action stops; early/full charge interpolate; cancel/death/cinematic/equip changes prevent late payload; no duplicate release from input plus notify plus timer. Compile actual production math independently and add Unreal behavioral automation for GAS/world integration. Run UE build/automation when required engine and content are available.

**Likely failure cases:** stale source weapon, external Blueprint payload double-application, character-visual collision resolving wrong owner, wall at muzzle, invulnerable target's link being severed anyway, runtime duration effects granting unowned permanent tags, stale timer releasing a later activation, synchronous callback canceling ability mid-target loop.

**Done:** native payload and feedback contracts complete; no parallel damage/resource/link system; behavioral tests provided; source checks pass; actual UE results and unavailable gates explicitly distinguished. Playable content acceptance additionally requires Axiom BP grant/allowlist and in-editor tests. Until that final gate passes, call this source-complete, not a validated playable build.

## Selection rationale

S1 has the highest immediate playability return: the paid shell, resource store, hostile filtering conventions, Shield transaction, command-link coordinator, handler cancellation, weak-point reveal and reward ledger already exist. A native Axiom payload connects them into a learnable player decision with bounded changes. Building a new encounter director or entire save/handoff framework first would leave Selene's action incomplete and create a larger unvalidated change. S3 and S4 remain mandatory campaign blockers; S1 does not claim to solve them.
