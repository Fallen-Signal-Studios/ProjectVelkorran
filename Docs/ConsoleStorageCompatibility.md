# Console account, storage and cloud pass

Date: 2026-09-05. Targets: Xbox Series X|S and PlayStation 5 family. This is source engineering evidence, not a console SDK build or certification result.

## Findings and changes

| Finding | Existing implementation preserved | Engineering change | Remaining validation |
| --- | --- | --- | --- |
| Online identity and cloud requests always used user 0. Local-player order can differ from platform storage ownership. | Configured `IOnlineIdentity` adapter, native account namespace and `UGameplayStatics` platform save backend. | Resolve the owning first campaign `ULocalPlayer` from its persistent game instance, obtain `FPlatformUserId`, and use `IPlatformInputDeviceMapper::GetUserIndexForPlatformUser`. Bind and clear login-status delegates for the resolved user; clear cached identity on reassignment. No physical controller ID or local-player array index is used as the save user. | SDK tests with a nonzero primary account, signout, controller reassignment and travel. |
| Startup eagerly read user-0 profile hints and allowed synthetic offline identity on every target. | Desktop offline profile restart and existing hash-only hint banks. | Non-desktop startup touches no user compartment until a real local account is known. `UsingLocalProfile` may authorize offline storage; a missing identity, `NotLoggedIn`, or a provider identity whose platform-user mapping differs from the owning player fences disk access. An unknown console identity never means an empty new profile. | Confirm the configured native console identity provider exposes a stable offline ID and matching platform-user mapping. Providers that cannot establish this remain unavailable; this pass does not invent platform login APIs. |
| The generic `IOnlineUserCloud` file protocol could be advertised on console merely because an interface existed. | Desktop opt-in, immutable cloud revisions, explicit conflict review and bank validation. | Generic manual cloud is disabled outside desktop at both transport and subsystem admission. `IsCloudManagedByPlatform()` exposes the distinction to UI. No parallel console cloud transport is added. | Configure and exercise the licensed platform save backend, including platform-managed synchronization/conflicts. The capability label does not prove that a platform backend has been installed or configured. |
| Signout and replacement accounts could leave the previous owner writable while identity was unknown. | Current campaign/load remains owned by its original account; account changes are frontend-only. | `IsPlatformStorageOwnerAvailable()` is the shared admission check for lifecycle/travel. Unknown or unauthorized device identity revokes access without relabeling data, cancelling a restore, or accepting another account's snapshot. Returning the original offline owner reauthorizes its existing namespace. | Interrupted load/write, offline boot, repeated signout/in, and account selection while a save-failure prompt is open. |
| Real-time save watchdogs and ticker deltas included suspended time. A save-failure pause could conflict with another pause owner. | Existing load request, acknowledged-boundary receipt and failure retry snapshot. | `SetPlatformSuspended()` starts no I/O, holds native storage/ticker work, extends only owned load/acknowledgment deadlines, and discards the first resumed ticker delta. Save failure uses the controller's named `SaveFailure` pause lease, including when another system already paused the world. | Root lifecycle integration, suspend during load and save failure, duplicate lifecycle events, and console shutdown/Quick Resume behavior. |
| Blueprint account selection could bypass the new console startup fence, and cloud cancellation listeners could run before an outgoing account was revoked. | Existing public selection entry point and cloud cancellation semantics. | Only a private, friend-restricted native account observation updates the authorization latch. Console selection must match its ID and user index before any profile-hint I/O. Observation revokes outgoing access before cancellation or account broadcasts. | Unauthorized public selection, wrong account/index, signout recovery and cancellation-listener reentry automation; real platform account changes during I/O. |
| Capturing the configured provider only during game-instance initialization could retain no identity forever or use a pre-world default in PIE. | Configured world-scoped OSS provider and exact ownership of draining requests. | Account polling lazily resolves the eventual game-instance world and retries deferred identity/cloud interfaces. Provider/interface replacement is allowed only after the owned request drains; old delegates remain attached until then. | Delayed local-player/provider readiness, PIE world scoping, provider loss/replacement and late delegates on the licensed engine. |

## Source and validation

Primary source files are `Private/Platform/SovOnlinePlatformServicesAdapter.cpp`, `Private/Platform/SovPlatformServicesSubsystem.cpp`, `Public/Platform/SovPlatformServicesSubsystem.h`, `Private/Save/SovSaveSubsystem.cpp`, and `Public/Save/SovSaveSubsystem.h`. Existing serializers, checksums, bank rotation, slot names and schema are preserved.

Executed: `Tests/Portable/SovPlatformServicesPolicyTests.cpp` compiled and ran with C++17, `-Wall -Wextra -Werror -pedantic -fsanitize=undefined -fno-sanitize-recover=all`. The suite adds 144 capability/ownership combinations, including nonzero and invalid users, device identity loss, and provider/platform ownership mismatch. `git diff --check` passed for the current worktree at this checkpoint.

The existing `SovSavePolicyTests.cpp` also compiled and passed under those flags with the required `-ISource/ProjectVelkorran/Private` include path: 32,768 admission combinations, 100 rotations, and bank/schema/slot boundaries. An initial invocation without that include path failed to locate its policy header; correcting the test command resolved it without a source change.

Added Unreal automation registrations, not executed here:

- `ProjectVelkorran.Campaign.PlatformServices.ConsoleOwnerRoutingAndSignout`: native serialized banks use user 3; an active offline owner remains valid; unknown identity fences writes; pending load ownership survives; replacement account adoption is deferred; managed platforms perform no generic cloud I/O.
- `ProjectVelkorran.Campaign.PlatformServices.SuspendHoldsStorageAndWatchdogs`: no write while suspended, duplicate suspend/resume idempotence, watchdog budget preservation, and a single discarded resume delta.
- `ProjectVelkorran.Campaign.PlatformServices.RevokeBeforeCloudCancellationCallbacks`: an active review's synchronous cancellation listener attempts an actual native-bank write after account reassignment; storage must already be fenced, and no outgoing bank may change.

The console owner test also rejects unauthenticated public selection before provider readiness, wrong ID/index pairs after authorization, and attempts to reselect a revoked owner. The private evidence-ingestion method cannot be called from Blueprint. `IsPlatformStorageSuspended()` is available to travel admission separately from identity availability; pending ordinary slot restoration already holds decoded `PendingNarrative` in memory and does not need to reopen platform storage during world initialization.

Existing platform runtime cases continue to cover desktop offline restart, account switching during pending load/failure, stale callback rejection, local-bank import preflight, immutable upload review and corruption rejection. They require the UE 5.7 build and automation run.

API grounding: Epic documents [`ULocalPlayer::GetControllerId`](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/ULocalPlayer/GetControllerId) as a legacy physical-controller identifier; the owning platform user is exposed by [`ULocalPlayer`](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/ULocalPlayer). [`IPlatformInputDeviceMapper::GetUserIndexForPlatformUser`](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/ApplicationCore/IPlatformInputDeviceMapper/GetUserIndexForP-) maps a platform user to the legacy local-user index required by the existing APIs. [`IOnlineIdentity`](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/OnlineSubsystem/IOnlineIdentity) provides the reverse identity-to-platform-user check. Public documentation may display a newer engine selector; the licensed UE 5.7 source headers remain the compilation authority.

## Required console validation before claiming support

The workspace has no licensed Xbox/PlayStation engine platform sources, SDK build, mounted console storage, system account picker or development hardware. Platform backend configuration, offline account identity, save-container limits and naming requirements, low-space behavior, platform synchronization conflicts, suspended-write completion, entitlement and platform-required user messaging remain SDK/hardware gates. No native console save synchronization or certification success is claimed by this pass.
