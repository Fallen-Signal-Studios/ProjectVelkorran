# Optional platform account and cloud services

The TDD v2 §§11.9, 15.16 and 15.17 platform-account/cloud source path is implemented by `USovPlatformServicesSubsystem`, the configured OnlineSubsystem adapter, and the existing `USovSaveSubsystem`. The campaign still has one save authority: the native two-bank envelope around Narrative's serializer. Cloud is a transport of those exact verified bytes, never a second checkpoint/world-state implementation.

## Account and offline behavior

The GameInstance subsystem initializes after the save subsystem and observes the configured world-aware OnlineSubsystem's `IOnlineIdentity`. It registers login-status and login-change delegates, samples current identity immediately, and polls once per second as a recovery check for providers with incomplete notification behavior. It does not call Login, AutoLogin, Logout, retrieve credentials, request consent tokens, or start a session. OnlineSubsystemNull and absent providers are unavailable cloud services, not simulated network storage. They use the deterministic offline profile.

A stable identity includes provider, ID type and provider ID before hashing. Only the opaque hash enters save headers and native bank names; raw IDs remain transient and are not logged. The supported campaign local user is index 0, matching the game's first local controller. A different account can be selected only in the frontend, outside a pending load, save write, failure decision or campaign transition. A campaign GameMode also blocks selection before its controller is ready, closing a travel-startup gap. Login events never clear a pending campaign load or acknowledge/release a paused write failure.

An actual different stable account fences outgoing-account disk access while retaining its live campaign and original namespace. Returning to the original account restores access. A connectivity change is different: NotLoggedIn/temporarily absent network ID retains the last positively observed identity and permits local saving; only optional cloud is disabled. Gameplay never waits for cloud or account login. Providers must be validated with offline stable-user identity, account replacement and local-user storage semantics on the actual target device.

The first online identity observed during a campaign explicitly started in the offline local profile is not treated as proof that a previous stable account was replaced. That campaign remains writable under its offline namespace until a safe frontend profile choice; it is not relabeled or silently uploaded.

Offline process restart also preserves the selected namespace when network identity is unknown. A fixed 88-byte profile hint contains only magic/schema, local index, generation, a 32-character namespace hash, a platform-name hash and CRC. It is partitioned by platform/local index in native save storage, uses two alternating banks and requires exact readback before a profile switch. Initialization restores the highest valid hint; invalid size, schema, characters, CRC, generation, platform or user reject without selecting it. No raw account ID or credential is persisted. Unknown identity leaves that hint-selected profile alone; a positively known different identity overrides only after safe frontend admission. Failure to persist a new hint keeps the previously selected profile, avoiding an apparently successful profile switch that cannot be recovered offline.

## User-controlled cloud flow

`SetCloudEnabled` is an explicit, account/session-scoped opt-in. It is off at startup and revoked when identity or capability changes. No cloud operation is initiated by local save success, campaign completion, loading a map or enabling the preference alone.

| Frontend operation | Effect |
|---|---|
| `IsCloudAvailable` | Capability/admission query; no I/O or login. |
| `InspectCloudSlot` | Exports a verified native bank and enumerates/reads the latest published revision for that logical slot. No local or remote copy is overwritten. |
| `GetCloudReview` / `OnCloudReviewChanged` | Exposes request GUID, phase, local/cloud presence and actual mission/time/difficulty metadata. A timestamp never authorizes a replacement. |
| `ResolveCloudReview(RequestId, KeepLocal)` | Publishes the exact reviewed local bytes as a new immutable cloud revision. No prior remote revision is overwritten. |
| `ResolveCloudReview(RequestId, UseCloud)` | Rechecks account, slot, envelope integrity, supported schema/product, required assets and Narrative/canon records; checks that current local bytes still equal the reviewed local bytes; archives both copies durably before asking the native two-bank writer to commit. Does not start campaign travel. |
| `CancelCloudOperation` | Invalidates the review/request before cancelling consumption. No local bank is changed. A previously issued immutable upload may already exist remotely, which is stated in the result. |

Three rolling autosave slots, ten manual slots and one checkpoint slot keep their existing bounds. Cloud import is frontend-only. Damaged local banks must go through existing informed recovery before cloud review, so damaged data is never mistaken for an empty local slot. Public import rejects unavailable required content before archive or bank mutation. Cloud clocks and cloud generation numbers never select the local bank: the native writer assigns the next local generation. Failed archive writes or archive readback abort before either native bank is touched. Failed native writes/readback retain the prior good bank and the separately archived reviewed copies.

## Real provider adapter and cancellation

The implementation calls the configured [`IOnlineIdentity`](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/OnlineSubsystem/Interfaces/IOnlineIdentity?application_version=5.5) and [`IOnlineUserCloud`](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/OnlineSubsystem/Interfaces/IOnlineUserCloud?application_version=5.5) interfaces through `Online::GetSubsystem(World)`. Runtime build dependencies are `OnlineSubsystem` and `OnlineSubsystemUtils`; platform-specific provider plugins/credentials remain separately configured. Epic's accessible API references were checked for the delegate and file APIs; the UE5.7 headers/UBT remain the compile authority for Monday validation.

The cloud adapter uses actual enumeration, file-list metadata, cached-file clearing, ReadUserFile/GetFileContents, and WriteUserFile. Upload success requires provider write completion followed by a fresh cache-cleared read and exact byte equality. An enumeration/network failure is never interpreted as "no cloud save". Both advertised file size and downloaded envelope size are bounded to 64 MiB before project deserialization.

Each revision name contains a slot prefix, padded UTC publication ticks and a random GUID. No DeleteUserFile is called. Existing remote revisions remain recoverable even with concurrent publishers because publication does not overwrite a shared filename; the generic interface has no conditional compare-and-swap contract. The lexically latest valid revision name is displayed as the latest published copy, not asserted to be the most progressed campaign; device-clock skew is visible through metadata and always requires a choice. At 32 recognized revisions per logical slot, further uploads stop with a storage-management message. Actual provider quota/filename limits can reject earlier. Product/platform storage management must supply approved cleanup/retention UX before shipping; this implementation never silently deletes older saves.

The subsystem consumes callbacks only for the exact request GUID, account namespace and expected phase while opted in. Ownership is established before calling the adapter because callbacks can be synchronous. Cancellation invalidates ownership first. A 45-second deadline ends user-visible waiting without changing local saves.

The provider adapter serializes operations and retains cancelled enumeration/read/write ownership until the original provider terminal delegate arrives. This is necessary because generic OSS completion delegates carry user/file identity, not a caller's operation ID. A timeout does not allow an old same-file callback to satisfy a new request. An indefinitely hung provider may therefore keep optional cloud unavailable for that session; offline play remains available. This campaign adapter is the sole project owner of these UserCloud operations; other future callers must coordinate through it rather than issuing indistinguishable same-user enumerations concurrently. Delegates and buffers are released on subsystem teardown. Provider callbacks follow Unreal's normal game-thread OSS contract; target providers must validate it.

## Validation and explicit remaining device work

Executed here: `SovPlatformServicesPolicyTests.cpp` compiled with C++17, warnings as errors, pedantic mode and undefined-behavior sanitization, then passed. The production-used policy covers all 64 cloud admission combinations, all 16 callback-consumption combinations, slot bounds, revision quota and size limits. No Unreal/UHT/UBT execution is claimed in this source-only environment.

Six Unreal automation tests under `ProjectVelkorran.Campaign.PlatformServices` exercise the real subsystem and native serializer/two-bank owner through deterministic mock platform and storage adapters:

1. Account changes during pending load and paused failure retain ownership; same-account NotLoggedIn still writes native banks; different identity fences outgoing-account writes; unavailable cloud never performs a network request.
2. Explicit review and upload, stale GUID choices, cancelled/superseded read callbacks, actual native bytes reaching the transport, provider failure, timeout and late completion.
3. Public required-asset preflight rejection before writes; the production commit boundary's durable review archives, last-good native bank, local generation assignment, stale-local comparison and torn-write failure. Successful bank commit is deliberately tested separately from content preflight because the fixture has no authored mission map; it does not pretend that such a fixture passed public import.
4. Actual serialized cloud bytes with wrong account, schema, slot and payload checksum fail closed before an import choice is offered.
5. Offline restart in a new subsystem from the actual persisted profile bytes rediscovers and updates the existing native campaign bank with unknown network identity. Wrong local-user partition, malformed namespace and unsupported hint schema fail; the schema test recomputes CRC so it exercises schema validation rather than merely checksum detection.
6. Real dynamic UI delegate listeners cancel during Reading/Writing notifications before provider dispatch, start a successor review during completion/cancellation, and deinitialize during Reading. Old dispatch/terminal cleanup cannot stomp the successor or clear its native upload bytes. Resources retire before terminal broadcasts, notifications use immutable value snapshots, and post-broadcast dispatch rechecks exact request/account/phase ownership.

Remaining external work is concrete: run UE5.7 build and automation; validate each configured provider's cloud interface, account/entitlement/parental restrictions, offline identity across restart, same-index OS-user replacement, callbacks on game thread, cancelled/hung operations, fresh server readback, 64 MiB/provider quota rejection and provider storage management; exercise real network loss and concurrent device uploads. Console certified storage, credentials/entitlement policies and device certification cannot be established by source edits. No provisioning, service login, network request or live cloud modification was performed for this implementation.

Achievements remain optional and are not fabricated from invented platform achievement IDs. The existing campaign/Technique completion state remains authoritative; publishing platform achievements requires the approved provider achievement catalog and reward-to-achievement mappings, then target SDK execution. No online requirement or speculative reward producer was added.
