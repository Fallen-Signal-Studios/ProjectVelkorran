# Campaign engineering delivery

This is the authorized engineering follow-through after the audit and native Axiom slice. The authoritative design remains the August 2026 TDD v2 plus the later approved roster/resource decisions in `CampaignV2ChangeLog.md`. The December attachment is superseded. [GameplayAudit-2026-09-04.md](GameplayAudit-2026-09-04.md) preserves the original 33-gap analysis and eight-slice roadmap; it is a baseline audit, not a claim that subsequent source work is absent.

The result is a substantially broader native campaign implementation over Narrative. It is **not a certified playable build or a claim that the entire TDD is finished**. The working repository excludes gameplay assets, maps and Narrative content; Unreal 5.7, UHT/UBT, the Windows toolchain and ZenDyn are unavailable here. Native source and authored tests can be delivered; compilation, Blueprint migration, content integration, animation/readability, packaged playthrough and performance remain real gates.

## Review fixes beyond feature completion

The pass also addressed defects that could otherwise survive a superficial feature checklist:

- Old source pawn access through Narrative's cached controller could reclaim the shared ASC after possession changed.
- First-time Selene initialization could inherit Tarrik factions, skill levels and points even when ability specs were cleared.
- Callback-triggered possession changes could make an old handoff clear a replacement avatar's abilities/effects.
- Stale timer callbacks and recovery could affect a newer transition or an unrelated pawn.
- A save-to-travel failure could leave Unreal's pending travel URL populated.
- Deferred restored actor GUID assignment did not refresh Narrative's lookup cache; destruction of an old actor could evict its replacement.
- Empty saved quest lists failed to clear quests created during a failed attempt.
- Same-pawn retry retained previous recharge/break timing instead of starting clean checkpoint delays.
- Source-side damage observers needed pre-mutation target tags and committed transaction identity to survive target callbacks safely.
- Dispatch needed an early input-recall latch, return-only shatter behavior and correct immunity semantics for its two control channels.
- Perk cleanup needed exact grant ownership and save/notification ordering, including reentrant callbacks.
- Pawn corruption records could be restored while the controller still named the source mission. An explicit destination barrier now restores the saved band before publishing character readiness.
- Failed actor/component serialization could overwrite a caller's last good record. Capture now commits its candidate only after every serializer succeeds; managed restore callers check deserialization success.

## Validation and release status

The portable runner compiles the same numeric/policy headers called by production code using C++17, warnings as errors, and undefined-behavior sanitization. Suites cover Axiom geometry/charge, combat transactions, campaign admission/skip policy, Echo award policy, Tarrik lane timing, encounter resources/state, Selene payload geometry, corruption bands and Technique budgets. The final execution record and unexecuted engine gates are listed in [CampaignEngineeringValidation.md](CampaignEngineeringValidation.md). The exact changed-file inventory is [CampaignEngineeringFiles.md](CampaignEngineeringFiles.md).

Unreal tests exercise actual World/GAS/actor/component paths where possible; fixtures explicitly supply unavailable content prerequisites. They are authored, not executed in this environment. Manual/editor gates include both protagonists' complete weapon loops; empty/exact/full Echo; front/rear/perfect/exhausted defenses; weak-point and sever consequences; Handler/Hound/Drone token and disable behavior; reward/drop replay; same-world and map handoff; disk-write failure; every M01/M02 checkpoint and canon gate; cinematic skip; frame-rate variation; Blueprint compilation/cook; accessibility and performance.

No `main` merge is authorized or performed by this delivery. The changes are intended for a review branch/draft PR with the engine validation limitations visible.

## Remaining engineering and integration limits

The original gap register remains relevant wherever the table above does not close a requirement. In particular:

- Later convergence missions still need their joint Resonance behavior and any explicitly authored in-mission protagonist transition. The new mission-boundary handoff does not implement these mechanics.
- Physical projectile reflection, weighted mitigation for mixed damage channels, and complete finisher/exertion behavior are not established by the new defense resolver. The existing negation, Poise and input/ability contracts remain the foundation for those decisions.
- Narrative persistence now propagates the failures used by the managed campaign path. This does not implement the complete rolling-autosave/manual-slot interface, save-version migration policy, platform/cloud integration, or general transactional rollback of every legacy plugin load caller.
- Companion co-action is a validated movement/arrival and canon-recovery contract. It is not a complete companion combat repertoire. Corruption supplies permission, contact, exposure, band and recovery ownership; mission-specific pressure and remedies still need their authored implementation.
- Actual enemy roles, weapon grants, ammo/drop assets, sever meshes, reaction animations, UI/audio feedback and mission events remain unverified because the binary project content is absent. Those items cannot be classified as absent from the creator's local project.
- UHT/API compatibility, Blueprint migration and cooked behavior remain unproven until the real UE5.7 build runs. Any defects exposed there must be fixed in native code where appropriate.

## Next three playable slices

1. **Integrate and validate the complete native combat greybox.** Clean UE5.7 build, Blueprint migration, one weapon loop per protagonist, one Dominion Handler/Hound fight and one Reformation Drone fight. Done means the new native payloads are the sole gameplay producer, all control/resource feedback is visible, and the behavioral automation plus repeated PIE fights pass.
2. **Prove M01→M02 through death, retry and disk load.** Author the mission assets, actual beat/Sequence events, extraction co-action, entry checkpoints, PlayerStarts, doors and target maps. Done means a recorded clean-boot playthrough plus restart at every critical gate, with no kit/faction/Technique/reward leakage and verified write-failure recovery.
3. **Prove a representative convergence/production encounter.** Build the TDD's authored companion/Resonance and corruption responses on the new contracts, finish the Technique/Equipment/Evidence UI subset and validate packaged content, accessibility and performance. Done means an approved playable build with measured encounter behavior and recovery, before expanding remaining campaign missions.

These next slices center on the actual content and engine evidence that cannot be established from this source repository alone. Any native defects exposed by those runs remain engineering work, not something a Blueprint workaround should conceal.
