Those are retained, with shared lifecycle fixes where this pass touches their execution.

Weapon-specific grants still belong to the equipped Narrative weapon and its actual ability handle. Echo spending remains in the existing native Echo transaction. Shield, Health, Poise, guard, perfect guard and deflection remain one central result path. Weak-point/disruption and sever remain distinct existing target capabilities, so a body hit is not arbitrarily converted into a dismemberment or command interruption. NPC death still owns finite drops, with encounter attempt cleanup preventing replayed sustain. Presentation remains driven by actual weapon state and native events. An alternate inventory, damage pipeline or AI runner would increase migration risk and was not added.

All those assertions concern source ownership. Actual attack montages, equipped grants, Ammo/Echo pickup classes, dropped mesh collision, bone/weak-point mappings, reaction readability and weapon socket positions must still be validated against the editor project.

## Level 1 and Level 2 end-to-end dependencies

The opening remains **M01 → M02** under the v2 campaign, not the old class-based Level 1/2 product. M01's heir/wounded-alive facts and M02's withheld shot are protected journal writes. M02 extraction still requires the actual Lyric arrival/co-action proof before its Sequence. Retry must restore that same journal, both protagonists' distinct resource/equipment/Technique records, command-link and weak-point state, and clear transient drops/projectiles exactly once.

Native progression can still be blocked by a missing mission/profile/PlayerStart, duplicate stable anchor or participant ID, incorrect active-hero requirement, unreachable mandatory beat, unregistered streaming destination, invalid quiet entry checkpoint, absent required save class, unavailable input/ability grant or a Blueprint that destroys a recoverable companion. These are surfaced by admission/validation where inspectable; asset dependency closure and actual authored events must be checked in the complete project. No source-only audit can certify the two maps play correctly end to end.

## Remaining work that is not editor authoring

1. **UE 5.7 integration and regression fixes.** UHT, UBT, module/link/API compatibility, real automation, commandlets and packaged execution have not run. The toolchain and binary project content are unavailable in this workspace. This is an engineering gate, not an editor task or a passing result. Any failures must be fixed before promoting the branch.
2. **Platform integration.** The native storage adapter and account namespace exist; actual platform account callbacks, certified storage semantics, cloud conflict handling, screen-reader announcements/focus behavior, channel-based haptics/controller audio and platform HDR calibration are not established by this pass. They need the target platform SDK/build and product decisions. No speculative network/cloud implementation was added.
3. **Measured performance and stability.** Run packaged CPU/GPU/memory/streaming captures, long session soak, process termination during writes, 100 death/retry cycles and full campaign transition loops. Tune actor/ability allocation, AI budget and streaming stalls from those measurements. Portable policies cannot establish frame rate or physics/readability thresholds.
4. **Future schema migrations.** Initial campaign disk schema 1.0 is implemented. No historical shipped v2 schema exists to migrate; future format changes require immutable fixtures and explicit deterministic migrations before release. December prototype saves intentionally do not masquerade as v2 saves.

There are also explicit **uncompleted native integrations**, not merely missing Blueprint assets: a full source/confidence/expiry threat-memory model and the campaign bridge into Narrative's existing Tier C/D Mass representation; gravity-aware lead for ballistic projectiles; menu focus memory/navigation wrap; platform screen-reader announcements and readable timed-choice integration; channel-based haptic routing; HDR calibration; and the remaining high-contrast/outline/navigation presentation consumers. Existing Narrative perception, targeting and gameplay settings continue to function, but do not prove these broader requirements. Their exact limits are recorded in [EncounterCoordinationEngineering.md](EncounterCoordinationEngineering.md) and [SettingsRecoveryAndDiagnostics.md](SettingsRecoveryAndDiagnostics.md). They need implementation against the actual engine, UI framework, content and approved target platform; they are not classified as delivered by a settings field or a policy test.
