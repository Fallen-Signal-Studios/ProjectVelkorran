## Account ownership and persistence

`USovSaveSubsystem` supplies native verified namespace/index observations and suspension state to private friend methods on `USovGameUserSettings`. Arbitrary UI profile strings cannot authorize preferences. Every I/O continuation compares namespace, index and owner generation. Revocation resets account values before notifications and applies neutral audio. Suspension restores committed in-memory values and initiates no preference write. Foreground reload checks the verified banks again. If a new account arrives while old I/O is active, a weak native ticker loads the current owner once that I/O unwinds; it does not require another account event.

`SovAccountSettings.cpp` uses the platform save API, two alternating banks, readback verification, a fixed bounded schema, generation, CRC and owner digest. The total profile is capped at 266,240 bytes; the embedded native input profile is capped at 262,144 bytes. Failed writes restore committed preferences and return failure to native settings controls. Physical display/HDR configuration stays with the device. Legacy global accessibility settings are not silently assigned to the first account that signs in.

`UNarrativeInputSettings` keeps the existing engine remapping/profile model. Its save and async-save entry points route to the verified account settings bridge. Native serialization records UE package/licensee/custom versions in a bounded frame (at most 128 custom versions), rather than reading native data under an implicit archive version. Account application retires previous profile maps and rebuilds them with the existing registered mapping contexts. The outermost context baseline is retained across nested owner replacement, including callbacks halfway through re-registration. Corruption and failed application retain the registrations needed to restore defaults. Native input capture and application use local byte snapshots so account reset cannot invalidate an in-flight archive's backing array.

The registered input LocalPlayer's native mapped user index must match the selected storage owner. The save/platform observer establishes that mapping; input does not rewrite platform identity. Other projects using the Narrative plugin keep their previous behavior through neutral defaults on `UNarrativeGameUserSettings`.

## Native save-review controls

`USovAccessibilitySettingsMenu` now exposes cloud revision metadata, explicit revision selection and separately confirmed deletion. It passes the exact cloud request/revision receipt to the platform subsystem; backend validation still owns import/deletion authority. Local preserved archives have slot-kind/slot selection, discovery, an archive cursor and separately confirmed deletion. The archive review stores `FSovStorageOwnerToken`, and stale/revoked owners cannot confirm it. Changing selection or retiring the menu cancels deletion intent. Current save banks are not deletion targets. Provider availability and backend recoverable-copy constraints remain authoritative.

2. The frame rejects unsupported/malformed bounded metadata before live mutation. Engine profile UObject deserialization remains an engine-owned boundary and must be exercised with real 5.7 profiles, malformed bodies and an engine-upgrade migration fixture. This is not a claim of a general hostile-file sandbox or a new account-authentication mechanism.
3. Old flat unheard-record saves lack the witness required to prove disclosure rights. Their serialized data is preserved, but automatically attributing it to the presently active protagonist would recreate the audit's knowledge leak. Product-approved migration requires known provenance; it is not inferred here.
4. The marker broadphase relies on normal Narrative character/Pawn collision. Validate authored Reformation/Dominion variants and mesh/capsule configurations, focused targets, occlusion and crowded encounters. No frame-time or console budget is claimed without capture.
