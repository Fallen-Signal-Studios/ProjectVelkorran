# Shared combat transaction repairs

Scope: audit ED-01, ED-02, ED-04 and ED-05. Source implementation and regression authoring are complete for the counterexamples below. UE 5.7 execution remains required. This is not a claim that GAS delegates provide an atomic multi-attribute database transaction.

Read current Health/Poise immediately before each remaining debit, freeze each packet's actual debit and zero crossing before its setter dispatches callbacks, and skip dead-body Poise. Bound recursive same-target packets to 32 active resolver frames. Heal meta packets cannot resurrect zero Health. Guard continuation against a destroyed or reassigned target and retire packets across an explicit Health restore using a native life epoch. ## Remaining proof and operational boundaries

1. Execute the native regressions against UE 5.7 with unity and non-unity builds. Host policy tests cannot validate GAS aggregator ordering, animation alignment, physics overlaps, replication or UObject lifetime behavior.
2. Attribute-change delegates can observe individual resource commits. The resolver preserves nested debits and freezes its own result rather than promising unobservable multi-attribute state. Native source-limit policies must remain synchronous, side-effect-free calculations; the current companion policy follows that contract. Explicit checkpoint restoration is a separate lifecycle operation, not a damage callback's way to resurrect a target.
3. Retained receipt memory follows the lifetime of the damage result that needs replay protection. Each receipt permits at most 32 consumer objects and eight channels per consumer; over-capacity admission fails. There is no actor-lifetime GUID ledger or blind eviction that silently re-enables old receipts.
4. The finisher outbox guarantees native event delivery for a committed outcome while its target survives. Authored phase consumers must apply progression idempotently by target/phase identity and restore their own saved state before the deferred pending delivery. A destroyed target cannot receive a gameplay event. The existing Narrative ASC readiness hook retains undelivered outcomes when actor initialization is late. Old checkpoints already affected by the original bug cannot be retrospectively distinguished from correctly delivered outcomes without content-specific recovery evidence.
5. Full pickups remain consumed if a recipient dies during a completed grant. A destroyed pickup is not resurrected for presentation. Real partial inventory acceptance, recipient handoff, streamed destruction and replication must be exercised in the engine build.

The resolver uses `SovCombat_ResolveAttributePacket` CPU trace scopes for the packaged capture gate. No packaged timing or console result is claimed here.

The final independent review also required fatal ownership to be rechecked after `OnOutOfHealth`, killed-enemy dispatch and target-result callbacks. A callback can restore the same target between those stages. The source receipt still records committed damage, but later source reward consumers cannot treat it as a fatal hit against the restored life. `RestoreDuringDeathAndResultPublication` exercises both actual callback boundaries. Notifications already delivered while the original life was current are not rolled back.

Cross-review also added native finisher activation epochs, deferred-end fences and post-team-policy reservation/strike checks. Those ability changes and their regressions are detailed in `PlayerCombatRepairs.md`. The shared component rechecks reservation, source epoch and target configuration after eligibility callbacks.
