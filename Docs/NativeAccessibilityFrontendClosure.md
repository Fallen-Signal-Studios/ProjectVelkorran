# Native accessibility frontend closure

Source implementation, 5 September 2026. This extends the existing Narrative/CommonUI frontend and `USovGameUserSettings`; it does not add a second settings, evidence or checkpoint store. UE 5.7/UHT/UBT and rendered device acceptance remain outstanding.

## Implemented producers and consumers

| Concern | Executable native path |
| --- | --- |
| Settings and first boot | `USovAccessibilitySettingsMenu` builds its real controls, safe-zone root and scroll container without widget assets. Native buttons support activation and left/right changes, coherent persisted transactions, full accessible labels, focused-control narration, boundary wrapping and CommonUI focus restoration. Explicit Continue records local first-boot completion; gameplay imports never infer it. The native controller/frontend host owns opening and pause/input lifecycle. |
| Local settings ownership | The existing snapshot gains independent UI/subtitle scale, caption background/names/direction/page limits, high contrast, four color palettes, independent opaque team/threat RGB overrides, outline thickness/toggles, navigation contrast/slow pulse, narration, pressure timing and controller-audio volume. Finite bounds are validated before any mutation. The portable gameplay payload remains exactly eleven bytes and cannot import these local preferences. |
| Subtitle and caption rendering | `USovAccessibilityPresentation` constructs real UMG text/background widgets. Speech uses separate cinematic/ambient anchors; important sound captions use a separate upper region. Unicode character-boundary pagination retains combining sequences and all page content; line/page limits and conservative viewport width constrain rendering. Speech pages have a minimum two-second readable interval. Negative-duration live dialogue retains its last page until the matched line-finish signal. Pause stops page time; scene reset retires text/history. Speaker names, stable shape tokens and textual ahead/behind/left/right indicators do not require color discrimination. |
| Independent scales and contrast | Native settings/review/control labels and marker labels consume UI scale; speech and sound captions independently consume subtitle scale. High contrast paints opaque black caption plates with white text and outlined marker labels. No application-global Slate scale is overwritten. Existing authored replacement widgets must use these same settings APIs. |
| Interactable/weak-point outlines | Actual `UPlayerInteractionComponent` focus/reach drives a two-tone screen-space bounds outline and interaction label. `USovWeakPointComponent::GetRevealedWeakPointAnchors` resolves the existing unbroken, actively revealed zone's bone/socket attachment; visible nearby native characters receive outlined diamond markers and a textual weak-point label. This is material-free screen-space outlining, not a claimed mesh-silhouette post-process. It does not enable hidden/unrevealed weak points. |
| Navigation | Only markers already admitted to the existing Narrative screenspace marker domain are displayed. Native triangle markers and labels consume the palette, contrast and optional slow pulse. The renderer is local-player/DPI relative. It does not create new objectives or reveal undiscovered map-only markers. |
| Evidence and history review | Settings opens `USovAccessibleRecordMenu` on the existing modal layer. Evidence comes only from the existing validated campaign acquisition history and the current protagonist's actual knowledge; stage is resolved from the same authority. Optional `ObservedFacts` and `Interpretation` extend the existing evidence definition and are rendered/read under separate labels. Legacy summaries remain explicitly unclassified, not automatically asserted as fact. Provided new text is checked by the shipping string-table validator. Current scene history comes directly from the presentation's bounded history; no transcript is saved/exported. Navigation and explicit Read use the completion-aware narration service when opted in. History changes, campaign replacement, widget removal and disabling narration cancel obsolete readouts. |
| Audio and haptics | The real menu exposes the existing Narrative audio buses, added ambience/tinnitus/dynamic-range APIs, controller-audio volume, and all existing haptic channels. Unsupported authored dynamic-range mixes return an explicit unavailable result. The feedback/audio implementations retain their existing owners. |
| HDR | Native controls edit peak, black floor, paper white and UI white requests. Black-floor changes use logarithmic steps. Real preview, explicit confirm and revert use the settings owner's receipt transaction; closing reverts the owned unconfirmed preview. An unsupported current HDR display is labelled unavailable. See the platform-output/display implementation notes for physical calibration ownership. |
| Optional cloud workflow | The native menu exposes session opt-in, manual-slot selection, review metadata and explicit publish-local/import-cloud/cancel controls through `USovPlatformServicesSubsystem`. Review shows mission, timestamp, play time and generation, never account identifiers. Provider/account/frontend capability gates the controls; neither review nor ordinary settings changes enable automatic synchronization. Closing only cancels the menu's still-current request. |

## Bounds and presentation decisions

Current-scene history retains at most 64 entries. Speech can queue 16 pending readable lines; overload retires the oldest pending line but leaves recent records available in current-scene review. Sound captions prioritize the latest critical event and paginate that event. This bounded behavior must be tested against the actual authored simultaneous-dialogue/cue rates. Weak-point discovery scans at most 256 native characters per refresh, paints at most 32 weak-point markers and 48 combined weak-point/navigation markers, and refreshes every 250 ms. Marker visibility and source admission are re-evaluated, not persisted as gameplay knowledge.

The native fallback is functional, not final art direction. Content work remains for localized fact/interpretation copy, language-specific line budgets, source dialogue/caption completeness, polished layout and optional mesh-silhouette materials. Existing authored HUD replacements must preserve the native host/layer integration or intentionally call the same adapters. Platform readers and controller-speaker hardware remain capability-specific; in-game completion-aware narration is not represented as external OS screen-reader completion.

## Validation performed and required

`Scripts/Tests/AccessibilityPolicyTests.cpp` compiled with C++17, warnings-as-errors and undefined-behavior sanitizer and passed: finite/layout/timing/color boundaries plus 10,000 slow-pulse samples. `git diff --check` passed. These are production policy tests, not evidence of rendering or OS speech operation.

Added Unreal automation sources under `ProjectVelkorran.UI.Accessibility`:

- `LocalSettingsAtomicPrivacy`: local scales/colors/timing/controller-audio and first-boot retention across the unchanged portable import, with nonfinite transaction rejection.
- `NativeControlTransactions`: actual native settings-control actions reach the settings owner, bounded wrap/decrease works, enum and boolean controls commit, and unavailable cloud capability is not offered as available.
- `PagingPaletteAndScenePrivacy`: retained page content, Unicode combining boundaries, independent team/threat overrides, live indefinite speech, caption consumption and scene cleanup.
- `EvidenceFactInterpretation`: unknown-stage summaries remain unavailable and legacy/classified records retain their fact-versus-interpretation labels.
- `RecordViewReentry`: CommonUI routed-focus callbacks deactivate/reactivate the same record-menu instance; the retired activation cannot rebuild or clear the successor's selected view. Native view generations also guard narration cancellation/error callbacks and settings-menu receipts against successor mutation.

These engine suites are authored but **not run in this environment**. Run them with the full frontend/dialogue/lifecycle suites after the UE 5.7 build. Then exercise actual keyboard/controller focus at maximum scales, small/ultrawide/split-screen viewports, localized expansion and shaping, caption bursts, speaker changes, pause/resume, nested settings/review modals, interrupted narration, physical HDR monitor changes and optional configured online providers. Screen-reader support and readable visual acceptance require the supported devices and player testing.

API compatibility checks used Epic's primary documentation for [UMG property synchronization](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/UMG/UWidget/SynchronizeProperties), [Unicode character-boundary iterators](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Core/FBreakIterator) and [Slate drawing primitives](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/SlateCore/FSlateDrawElement). Rolling pages can show a later engine revision; the UE 5.7 headers remain the build authority.
